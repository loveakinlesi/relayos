## Install

```sh
pnpm add @relayos/postgres
```

Peer dependency: `@relayos/core`

## Exports

| Export | Kind | Description |
|--------|------|-------------|
| `createDb` | Function | Creates a Drizzle ORM database connection to Postgres. |
| `createPostgresExecutionStore` | Function | Creates an ExecutionStore implementation backed by Postgres. |
| `executions` | Constant | The Drizzle table definition for executions (for direct queries). |
| `runMigrations` | Function | Applies RelayOS's Postgres migrations. |
| `Db` | Type | Type of the database connection returned by createDb. |

## Types

### Db

```ts
type Db = ReturnType<typeof createDb>;
```

The Drizzle ORM database connection type, pre-configured with RelayOS's Postgres schema and tables.

## Functions

### createDb

```ts
function createDb(connectionString: string): Db;
```

Creates a Drizzle ORM database connection to a Postgres database using a connection string. The connection is pre-configured with RelayOS's `relayos` schema and table definitions. Pass the resulting `Db` to `createPostgresExecutionStore()` and `runMigrations()`.

### createPostgresExecutionStore

```ts
function createPostgresExecutionStore(db: Db): ExecutionStore;
```

Creates an `ExecutionStore` implementation backed by Postgres. All executions, steps, and logs are persisted in the `relayos.executions`, `relayos.execution_steps`, and `relayos.execution_logs` tables. The store handles deduplication of events by `eventId` and maintains an append-only audit trail of step attempts.

### runMigrations

```ts
function runMigrations(db: Db): Promise<void>;
```

Applies all RelayOS Postgres migrations to your database. Migrations create the `relayos` schema and three tables: `executions`, `execution_steps`, and `execution_logs`. Call this once during application startup or setup. Migrations are idempotent and ship with the package, so no separate migration files are needed.

## Constants

### executions

```ts
const executions: PgTable<...>;
```

The Drizzle table definition for executions, exported for custom queries. Available columns: `id`, `eventId`, `eventType`, `eventData`, `status`, `attempt`, `replayedFrom`, `createdAt`, `completedAt`, `error`.

## Usage

```ts
import { createDb, createPostgresExecutionStore, runMigrations } from '@relayos/postgres';

// Set up database
const db = createDb(process.env.DATABASE_URL!);
await runMigrations(db);

// Create a relay with Postgres persistence
const relay = createRelay({
  database: createPostgresExecutionStore(db),
  plugins: [/* ... */],
});
```

All executions, steps, and logs are now persisted in Postgres. The tables live under the `relayos` schema to avoid conflicts with your application's own tables.

## Schema

RelayOS uses a separate `relayos` schema in Postgres with three tables:

- **executions**: Event executions with status, attempt count, and error details.
- **execution_steps**: Durable steps (append-only audit trail).
- **execution_logs**: Runtime and handler log entries.
